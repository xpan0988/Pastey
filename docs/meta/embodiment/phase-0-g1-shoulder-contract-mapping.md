# Phase 0 — G1 Right-Shoulder-Pitch Contract Mapping

## Status and scope

**Status:** Documentation-only, one-path semantic contract mapping. **Prototype gate: NOT YET PASS.** This specifies proposed Phase 0 obligations, not implemented Pastey embodiment behavior, a Unitree controller, a physical safety mechanism, or a wire schema. This refinement began at Pastey HEAD `70b6bf4845417176d591da3ac3721dc1bc63c4cb` with a clean working tree.

The only claimed task effect is one **bounded simulated G1 right-shoulder-pitch transition**. Other-motor support may be an *admission dependency* of the chosen simulator run; it is not a whole-body effect claim. No walking, manipulation, hand control, or general arm planner is implied. The semantic capability label `sim.g1.right-shoulder-pitch.bounded-transition.v0` is local to this mapping; it does not establish a global naming language.

**Evidence vocabulary:** **SOURCE FACT** denotes implemented Pastey or inspected official platform behavior at the linked revision; **OWNER DECISION** denotes a binding Phase 0 choice below; **PHASE 0 CONTRACT** denotes a proposed, unimplemented obligation; **INFERENCE** denotes a source-limited consequence; **OPEN QUESTION** denotes a required choice or unavailable proof. Earlier **CURRENT SOURCE** labels below have the same meaning as **SOURCE FACT**. Existing [Constitution](constitution.md), [Phase −1 reuse decisions](decision-record-v0.1.md), and [platform reconnaissance](g1-mujoco-platform-reconnaissance.md) remain unchanged.

## Task authority

**PHASE 0 CONTRACT:** The human reviewing principal approves this exact simulated task and its declared modeled-risk envelope; META Core is the authoritative grant/acceptance owner. A single task grant is tied to exact Plan/revision/approval/attempt, exact `HostRef`, exact bound simulator/controller/enforcer instance, slot `22` and named joint, a parameterized target region strictly within the modeled joint range, permitted PD-plus-feedforward `LowCmd` family (`q`, `dq`, `tau`, `kp`, `kd` bounds), the whole-packet treatment for other 28 motors, monotonic local validity interval, candidate/state freshness, entry/hold/exit predicates, conflict exclusion, and a recovery ceiling of **observe/reconcile only**. It authorizes one target transition, not arbitrary repeated commands, an arm sequence, or an inverse recovery move. The exact *joint-only* effect criterion appears below; any supporting-base condition needed to admit the selected simulator configuration is a separate predicate and cannot quietly enlarge the accepted claim.

The grant may narrow but never widen the reviewed task. The enforcer checks the current local grant and each full command candidate before publication; Core records admission and effect-governance decisions. An expired approval, wrong attempt/Host/map, unsupported control family, stale state, missing candidate, or unknown publication ownership denies admission or ends task progression. A command published before revocation may still have residual modeled effect; authority termination is not an effect-reversal claim.

A Core revocation **request** and locally enforced revocation are distinct facts. The enforcer must acknowledge when it fenced task publication and began any separately authorized protective response. If that acknowledgment cannot arrive, Core cannot claim local intervention occurred; the preauthorized local expiry and maximum disconnected exposure still bound task authority. The clock/skew and disconnected-exposure limits remain parameters to qualify before admission. Network silence is neither a protective acknowledgment nor evidence that the simulator stopped. [Constitution real-time invariant](constitution.md#real-time-authority-invariant)

**Representation boundary:** Current `AuthorityContextV1` and `EffectEnvelopeV1` are digital-only in their fields. Physical task scope, time, and protective relation must eventually lower into **the same authoritative META effect-governance spine and decision/evidence history**, with an explicit versioned physical boundary; this is not a fifth `EffectEnvelopeV1` ceiling and not an `AuthorityLeaseStore`. The exact type, durable representation, and local grant projection remain unresolved. [Current context and envelope](../../../src-tauri/src/effect_authority.rs#L77), [reuse D6](decision-record-v0.1.md)

## Protective authority

**OWNER DECISION / PHASE 0 CONTRACT:** A human operator reviews a separate, simulation-only protective grant; META Core issues and records it through the one authority spine, and Local Enforcement alone admits its command effect. It is bound to the simulator, exact protective implementation, complete packet policy, response bounds, and terminal/maintenance semantics. Task expiry cannot reduce it to an arbitrary short TTL. Protection can progress locally until its declared terminal condition under its *own* continuing conditions. An unknown grant never authorizes protection. This is new physical semantics; current process-local `EffectAuthorityStateV1` cannot serve as a durable grant. [Pastey state](../../../src-tauri/src/effect_authority.rs#L1387-L1425), [Phase −1 D6/D10](decision-record-v0.1.md)

The SDK2 `LowCmd_` at `9754cd153af3da471b0fe5f3aa535e426fb11db3` has 35 wire slots, while pinned `G1Example::LowCommandWriter` fills 29 motor entries. ### Protective authority lifecycle and exit

**PHASE 0 CONTRACT:** Entry triggers are task-grant expiry/revocation, critical state or candidate staleness, writer ownership uncertainty, controller loss, or local intervention. Local Enforcement records the triggering evidence and Host monotonic time, fences the old attempt, checks the *separate* protective grant and exact binding, then admits only the bound full-packet protective behavior. It evaluates continuing grant, writer ownership, response and state evidence at declared watchdog intervals; false or unknown means no assertion of protective success, escalation to the human reviewing principal/Core, and an explicit residual-effect-unknown report. A selected fixed full-packet capability may be authorized to publish during a bounded `LowState` outage if it needs no external state candidate and the bridge's internal-sensor dependence is part of its bound contract; its effect remains **unknown** until fresh evidence returns. Whether continued publication is allowed after `T_protect` without such evidence must be specified in that capability's unknown-mode envelope. The response-start bound and observation window are reviewed parameters. Local protection needs no fresh remote decision while its grant remains valid, but unknown-mode publication cannot silently become unlimited authority.

**SOURCE FACT / exit constraint:** `RobotBridge::run` reuses its stored `LowCmd` on later iterations. Therefore “terminal reached” cannot mean “stop publishing, so actuation ceased.” A last damping or hold packet may continue to generate modeled actuator control. [Pinned bridge `RobotBridge::run`](https://github.com/unitreerobotics/unitree_mujoco/blob/1eb6642e3f3fdfb7fb13a9794fd6a2dd93ea0e7d/simulate/src/unitree_sdk2_bridge.h#L161-L180), [pinned SDK subscription storage](https://github.com/unitreerobotics/unitree_sdk2/blob/9754cd153af3da471b0fe5f3aa535e426fb11db3/include/unitree/dds_wrapper/common/Subscription.h#L24-L45)

**PHASE 0 CONTRACT — required distinction:** (1) authority to *initiate* protection permits the trigger and first bound packet; (2) authority to *maintain* protection permits continuing publication or intentionally retained application of that packet within a declared envelope; (3) the *terminal condition* is an observed joint-scoped effect criterion below, not proof of whole-body safety; (4) *residual modeled effect* remains a distinct observation after terminal. The terminal may mean no further **change** in protective command is required, but it cannot automatically mean protective actuation has ceased. A persistent terminal-maintenance state would need its own bounded authority, continuing evidence and exit/handoff rule. Alternatively, a proven zero-actuation or native support handoff could end protection; none is established here. Simulator pause/disable can be a separately reported test intervention, but using it as an implicit terminal erases the retained-command question rather than answering it.

**OPEN QUESTION / blocker D:** Choose the post-terminal status of the complete packet and its continuing modeled effect: authorized terminal maintenance with evaluator/enforcer and eventual exit, qualified handoff to another bound capability, or demonstrated cessation of actuation. No inspected official source supplies that authority transition or shows that `|dq[22]|` near zero makes retained actuation harmless. `T_protect` below is a response/observation deadline, **not** an arbitrary expiry of otherwise active protection.

## Local enforcement ownership

**OWNER DECISION / PHASE 0 CONTRACT — meaning:** For this *controlled simulator harness*, the enforcer is the only configured process with a G1/HG `rt/lowcmd` writer on the selected DDS domain/interface/bridge instance. Every task-producing full packet, including support fields for the other 28 motors, is a native candidate until the enforcer locally checks and publishes it. A protective capability may produce candidates, but only this enforcer can admit and publish them. The task controller and any support/protective provider have **no** `rt/lowcmd` publisher; no second task, example controller, or locomotion process joins this domain. The private candidate channel can be IPC or in-process, but its implementation must be unable to reach the bridge's topic without the enforcer. A single configured publisher is a harness property, not a DDS authentication guarantee.

**SOURCE FACT:** The pinned simulator `RobotBridge` creates a `LowCmd` subscriber on `rt/lowcmd`; the pinned SDK2 `G1Example` creates a `ChannelPublisher<LowCmd_>` explicitly and calls `Write`. `ChannelFactory::Init(domainId, networkInterface)` and `CreateSendChannel` make domain/interface and writer creation explicit. The SDK example as written is **not** the candidate-only controller because it owns a writer; it must not run unchanged in the Phase 0 task topology. [Pinned bridge `RobotBridge`](https://github.com/unitreerobotics/unitree_mujoco/blob/1eb6642e3f3fdfb7fb13a9794fd6a2dd93ea0e7d/simulate/src/unitree_sdk2_bridge.h#L141-L180), [pinned SDK2 `G1Example` publisher](https://github.com/unitreerobotics/unitree_sdk2/blob/9754cd153af3da471b0fe5f3aa535e426fb11db3/example/g1/low_level/g1_ankle_swing_example.cpp), [pinned SDK2 `ChannelFactory`](https://github.com/unitreerobotics/unitree_sdk2/blob/9754cd153af3da471b0fe5f3aa535e426fb11db3/include/unitree/robot/channel/channel_factory.hpp#L14-L52)

**SOURCE FACT / detection limit:** Eclipse Cyclone DDS **documentation version 11.0.1** (supplemental API reference, not an identified pinned Unitree dependency revision) documents `dds_get_matched_publications(reader, ...)` and `dds_get_matched_publication_data` for **writers matched to that reader**; its discovery behavior matches by topic, type, and QoS. A harness monitor or instrumented bridge reader could observe an extra matched endpoint **if the deployed DDS version exposes this API**; the pinned Unitree bridge does **not** expose that monitor. Matching is eventual and compatibility-dependent. Endpoint handles/GUIDs and process inventories are diagnostic evidence, not cryptographic principal identity, a writer exclusion mechanism, or proof that no unobserved writer exists. **INFERENCE / harness assumption:** Prevention through controlled process topology is stronger than relying on discovery: start one pinned bridge and one enforcer writer in an isolated, recorded DDS domain/interface; launch only candidate-only controllers; record a process/writer allowlist; fail admission if the topology cannot be attested. This is an experimental configuration assumption, not universal DDS security or protection against a malicious local process. A domain number alone does not exclude another participant. Extra matched writers, unexpected participating processes, monitor loss, or a topology change make ownership **unknown** until resolved.

### Task terminal condition

**PHASE 0 CONTRACT:** Define distance `d(q,R_target)` as zero inside the reviewed target interval and distance to its nearest boundary otherwise. A **crossing** is a momentary passage into/through that interval; **reached** is one qualified sample with `d(q,R_target) ≤ E_q`; **settled** requires `d(q[22],R_target) ≤ E_q` **and** `|dq[22]| ≤ E_dq` consistently on every qualified, ordered sample across an advancing-simulation-time window of length `T_settle`, with gaps ≤ `T_gap` and no Host-age, map, grant, ownership, or attempt-continuity violation. This is sampled modeled evidence, not proof of every instant between samples. `tau_est[22]` is recorded for modeled response/anomaly review, not a fabricated torque threshold. EV makes the observed-effect verdict; Core accepts the exact reviewed joint intent only after the corresponding eligible disposition and settled evidence. A controller success report, target crossing, isolated in-range sample, or DDS write never substitutes for this. [Pinned state path](https://github.com/unitreerobotics/unitree_mujoco/blob/1eb6642e3f3fdfb7fb13a9794fd6a2dd93ea0e7d/simulate/src/unitree_sdk2_bridge.h#L175-L209), [Phase −1 D8](decision-record-v0.1.md)

**Task exit is a separate authority transition:** Settled effect and Core acceptance do not make the bridge forget its last *task* packet. Before ending task authority, the harness must place continued modeled actuation under a separately valid maintenance/protective capability or prove an authorized transition to no task actuation; it may report the effect verdict while that transition remains pending. A terminal task verdict cannot silently license retained task control. This is the same retained-command issue as protective exit and is included in blocker D. [Pinned bridge command loop](https://github.com/unitreerobotics/unitree_mujoco/blob/1eb6642e3f3fdfb7fb13a9794fd6a2dd93ea0e7d/simulate/src/unitree_sdk2_bridge.h#L161-L180)

### Protective terminal condition

**PHASE 0 CONTRACT — conditional on selecting a complete protective capability:** `DampedCommandV0` may be called *joint-terminal* only if task publication is fenced, its exact protective packet/disposition is recorded, writer ownership and grant remain valid, and fresh ordered slot-22 samples remain consistently in declared `R_protect` with `|dq[22]| ≤ E_protect_dq` across `T_protect_settle` with gaps ≤ `T_gap`; the response must begin by `T_response` and be observed or classified failed/unknown by `T_protect`. This means sampled modeled joint velocity entered the reviewed terminal region. It does **not** mean the robot is safe, all 29 joints stopped, actuator control ceased, or protection may be abandoned. An in-range sample without a complete protective packet is not a protective effect verdict.

**Protective outcomes:** **failure** means qualified evidence contradicts the declared response/terminal bound (including missed response deadline); **effect unknown** means missing/stale/ambiguous state, writer conflict or uncertain packet application; **terminal reached** means the joint criterion and protective disposition are qualified; **terminal maintenance** means separately authorized continued application of a complete bound packet or a qualified handoff. LE fences task in all four cases, records local disposition and escalates failure/unknown. Which maintenance/handoff/cessation rule is valid remains blocker D above. No finite `T_protect` can silently end active modeled actuation.

## Completion: Disposition → Observed Effect → Acceptance

1. **Disposition (enforcer/authority fact):** Core and enforcer record whether the attempt was never admitted, admitted, each candidate allowed/denied/unavailable, each packet attempted for publication, task authority ended, and protection was requested/attempted. An allowed effect decision or DDS write says nothing by itself about simulated actuation. The current digital `EffectDecisionV1` provides the decision meaning, not a physical completion status. [Current decision](../../../src-tauri/src/effect_authority.rs#L1247)
2. **Observed Effect (qualified simulation fact):** A verifier evaluates fresh slot-22 `q/dq` traces against the reviewed target and `T_settle`, retaining `tau_est` as modeled response evidence. It records partial movement, target crossing without settling, stale/contradictory evidence, or unknown effect. Any broader support witness qualifies *admission* only unless a different effect was explicitly reviewed. No `LowState` sample itself proves the intended command caused the position.
3. **Acceptance (META Core verdict):** Core may accept only the exact reviewed simulated shoulder effect when disposition and qualified observed effect agree, the bound attempt remains eligible, no revocation/intervention forbids acceptance, and witness sufficiency is met. It can record “effect verified but intent unaccepted” where posture evidence exists but authority/correlation failed. Later evidence creates a linked revised verdict, not silent historical replacement. [Current digital acceptance pattern](../../../src-tauri/src/managed_execution.rs#L699), [reuse D8](decision-record-v0.1.md)

## Failure and terminal outcomes

This path permits **never admitted; admitted with no confirmed actuation; partially effective; target crossed but not settled; observation stale; effect unknown; protective transition entered; protective outcome failed/unknown; effect verified but intent unaccepted; accepted**. These are semantic dispositions/observations/verdicts for this path, not a new universal enum. A terminal nonacceptance may coexist with continued physical evolution or protective observation. A stale state never becomes inferred success; command cessation never becomes inferred stopping; one accepted shoulder angle never becomes whole-body safety.

## Recovery and reconciliation

**OWNER DECISION:** Authority loss, critical state staleness, ownership loss, or restart ambiguity terminates the *old task attempt* for progress. Core records interruption; LE rejects every old candidate. Reconciliation precedes any new task-producing motion, which needs a new attempt, fresh admission, and fresh authority. This is true even if a later shoulder sample happens to be inside `R_target`; it may support an observed-effect report but cannot revive invalid task authority. No blind inverse command or automatic return to the initial angle is authorized.

**SOURCE FACT / reuse limit:** Pastey's `EffectAuthorityStateV1` is process-local and initializes an empty store after restart. `bridge_plan_v2::reconcile_startup` interrupts accepted digital attempts. These support conservative no-resumption semantics but do **not** reconstruct physical protective authority or stop the simulator. **OPEN QUESTION / blocker E — restart protection:** D-P0-3 permits autonomous local protection *only if a valid protective grant is locally checkable after restart*. No implementation or persistence mechanism is chosen here.
